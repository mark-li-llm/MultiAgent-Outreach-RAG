## Research Question

Research the codebase to support building a minimal web demo for investor showcase at an entrepreneur conference. Document what exists in the codebase and output directories - identify relevant file contents, data structures, and components that can be leveraged for the demo. Focus on:

1. Pre-generated email outputs and their structure
2. Email data structure (JSON/file format, fields, organization)
3. What data is saved in different states
4. Existing web/API components
5. Minimal dependencies for a read-only demo

## Summary

The codebase contains **37 pre-generated email sessions** for Salesforce (34 older + 3 brand new from October 13, 2025). All outputs follow a consistent 5-file JSON structure in `outputs/<session-id>/`. Each session includes a full state snapshot in `state/session-<session-id>.json` that captures the entire AgentState dictionary with company, persona, queries, routing decisions, and all intermediate processing data.

**Key Finding**: NO web UI currently exists. The system has backend MCP HTTP stub servers (ports 7801-7805) for agent-to-agent communication, but no Flask/FastAPI applications, HTML templates, or frontend frameworks. A minimal demo requires only Flask or FastAPI (~50-80 MB) versus the full pipeline environment (~4.5 GB with 38 packages).

**Latest Outputs**: Three new sessions were just generated today (October 13, 2025):
- `test-langgraph-vp-sales-2025` (VP Sales Operations persona)
- `test-langgraph-vp-cx-2025` (VP Customer Experience persona)
- `test-langgraph-cfo-2025` (CFO persona)

  "body": string,                 // Email body with bullet points

### 3. Data Saved in Different States

#### State Snapshot Files

**Location**: `state/session-<session-id>.json`
**Count**: 37 files (matching 37 output sessions)

**Purpose**: Full AgentState dictionary capturing all intermediate processing data for replay and debugging.

#### AgentState Schema

**Complete State Structure** (state/session-test-langgraph-vp-sales-2025.json:1-246):

```json
{
  // Input Configuration
  "company": string,              // Target company name
  "persona": string,              // Recipient persona
  "session_id": string,           // Unique session identifier
  "timestamp": string,            // ISO-8601 timestamp

  // Planning Phase
  "queries": string[],            // Generated search queries (typically 5)
  "persona_keywords": string[],   // Persona-specific keywords (EMPTY in current outputs)

  // Retrieval Phase
  "retrieved_chunks": any[],      // Retrieved document chunks (EMPTY - not persisted)
  "retrieval_logs": [             // Per-query retrieval metadata
    {
      "query": string,
      "results": any[]            // EMPTY in state files
    }
  ],
  "route_decisions": [            // Router decisions per query
    {
      "query": string,
      "backend": string,          // "faiss" | "pinecone" | "weaviate"
      "reasons": string[]         // Routing reason codes
    }
  ],

  // Synthesis Phase
  "insight_candidates": any[],    // Raw candidates (EMPTY - not persisted)
  "insight_cards": [              // Final 5 LLM-enhanced insights
    {
      "id": string,
      "title": string,
      "summary": string,
      "url": string,
      "date": string,
      "evidence_snippet": string,
      "confidence": number,
      "source_domain": string,
      "doc_id": string,
      "persona_relevance": {...},
      "metric_impact": {...},
      "action_suggestion": string
    }
  ],

  // Generation Phase
  "email_draft": {               // Generated email content
    "subject": string,
    "body": string,
    "unsubscribe_block": string,
    "company_info_block": string,
    "proof_points": [...]
  },

  // Compliance Phase
  "compliance_flags": string[],   // All flags (critical + warnings)
  "a2a_rounds": number,           // Number of A2A negotiation rounds

  // Observability
  "metrics": {
    "nodes_executed": any[],      // EMPTY in current outputs
    "timings": {}                 // EMPTY in current outputs
  },
  "errors": any[]                 // EMPTY (no errors in successful runs)
}
```
